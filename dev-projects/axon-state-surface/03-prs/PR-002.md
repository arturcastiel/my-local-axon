## Summary
Rewire menu.md (+ compiled twin menu.cmp.md) to consume `snap.backup` / `snap.plans` (from PR-001)
instead of hand-resolving paths; add one degraded-safe arm per render branch so a failed/degraded
snapshot renders "snapshot unavailable"/silent, never a false "not configured". Keep today's proven
os-warn logic (no noise regression). Add six static neuron-text invariants as the CI-enforceable
guard (run.py does NOT execute the render).

- PR-001 merged: snap.backup {enabled,url,status,last_push} + snap.plans {active_count,done_count,active_stems} available.

### tests — static neuron-text invariants (a)-(f) over BOTH menu.md + menu.cmp.md
- (a) backup/plans sourced from snap.*, no render READ(/SCAN(.
- (b) per-line: every line whose OUTPUT contains "not configured" has, in its CONDITION (left of →),
      BOTH `snap.backup ≠ ∅` AND `snap.backup.enabled` with `≢`/`≠` "true", joined by ` AND `, no ` OR `,
      no `≡ ∅`; the degraded arm OUTPUT contains "snapshot unavailable".
- (c) os-warn backup term is exactly `snap.backup ≠ ∅ AND snap.backup.enabled ≡ "true" AND snap.backup.status ≡ "error"`; no not-configured in os-warn.
- (d) plans sourced from snap.plans (no SCAN(); fields exactly {active_count,done_count,active_stems}.
- (e) workspace-backup.md status WRITE vocabulary is exactly {ok,error}.
- (f) no deleted gather var `backup-(enabled|url|status|last)` or `plans-(active|done|count)` survives.
